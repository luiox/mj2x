# 字符串 at-rest 加密（String Encryption）

> 发射期加密字符串常量，首次访问时解密；产物里没有明文字面量。

| 项 | 值 |
|---|---|
| 对标术语 | jvmtp `obfuscation.strings`；业界通称 string encryption |
| 作用层 | 发射端（发射期加密）+ 运行时（首次访问解密） |
| 开关 | `--strings-encrypt` |
| 后端 | StackC ✅ / RegC ✅ / LLVM ❌ |
| 默认 | 关 |
| 状态 | ✅ 已落地 |

## 对抗什么

字符串是仅次于常量的第二强语义锚点。`strings` 扫一遍产物拿到 `"SELECT * FROM"`、
`"AES/CBC/PKCS5Padding"`、错误文案、URL，算法的用途和位置基本就定位了。

这一项防的就是最朴素的那种攻击：不用反编译，一条 `strings` 命令。

## 机制

- **发射期**：字符串常量以密文形式进入产物。
- **运行期**：首次访问时解密。

"首次访问解密"意味着解密后的明文在内存里——at-rest 加密只管静态产物，不管运行时
内存。这是与 VM 懒解密不同的定位：后者连未执行分支的内存态都保护。

## 代价

| 维度 | 影响 |
|---|---|
| 性能 | 每字符串首次访问一次解密；重复访问走缓存 |
| 产物体积 | 密文 + 解密代码，小幅膨胀 |
| 覆盖面 | 只覆盖发射期可见的字符串常量；运行时拼接出来的字符串不在范围内 |

## 已知绕过面

- **运行时 dump 内存**：解密后的明文就在堆里。这一项只对抗静态。
- **解密例程是可定位的**：找到解密函数，下断点即可拿到所有字符串。
- 与**立即数隐藏**同族局限：防"扫"，不防"算"。

## 与其他技术的关系

- 与**立即数隐藏**互补：一个隐藏数值常量，一个隐藏字符串常量。
- 与 **VM 程序加密**定位不同：后者保护的是指令流，且支持按块懒解密（未执行块
  保持密文）；本项只做 at-rest。
- LLVM 后端不支持（PARAM 的 backends 面已限 `stackc|regc`）。
